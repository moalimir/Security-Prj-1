# Project completion plan

Current implementation, verification limits, instructor approval, and remaining
submission work are maintained in [Project status](project-status.md).
This replaces the earlier completion percentages and draft role assignments;
those were not evidence of a grade or of actual team contributions.

## Completion gates

1. Keep code and documentation aligned with the JSON contract, source-site
   matching, configured regression corpora, and both unseen-patch CLI entry points.
2. Verify the final source revision in hosted CI. Preserve its exact commit,
   reports, generated cases, and replay artifacts. Historical Linux measurements
   are retained in [Linux verification](linux-verification.md).
3. Retain the team's confirmation of instructor approval alongside both target
   studies, provenance, harness interfaces, independent reference tests, and
   expected outcomes. See the [approval record](project-status.md#instructor-approval-confirmed-by-the-team).
4. Package tracked sources/configs with ignored reports and bundles, reconstruct
   targets offline in a fresh workspace, and verify the resulting submission.

Team contribution and individual defense remain outside the current assessment.
The assignment's stated deadline is 18 Aban 1405; any extension requires an
actual course announcement rather than an assumption in this plan.
