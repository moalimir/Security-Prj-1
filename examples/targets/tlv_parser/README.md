# TLV parser target

This original, self-contained C training target deliberately contains a heap
overflow in `base/tlv_parser.c`. It is intended only for patch validation.
`tools/prepare_targets.py` copies `base/` into a standalone repository and applies
each patch independently against `base`, producing sibling revisions `correct`,
`incomplete`, `regression`, and `hardening_weak`.

## Protocol v1

All lengths and header fields are unsigned bytes. A packet begins with four
bytes: magic `0x54` (`T`), version `0x01`, top-level record count, and flags `0x00`.
Exactly that number of records must follow, consuming every input byte.
Each record has a tag byte, payload-length byte, and exactly that many payload
bytes. Empty packets, truncated headers/payloads, unknown tags, invalid header
fields, mismatched counts, and trailing bytes are errors.

| Tag | Payload | Exact output |
| --- | --- | --- |
| `0x01` | 0–16 ASCII bytes (`0x00`–`0x7f`) | `LABEL:` + original bytes + newline |
| `0x02` | Exactly 4 bytes, unsigned big-endian | `UINT32:` + decimal integer + newline |
| `0x03` | Exactly one complete inner TLV record | `NESTED->` + inner record output |

ASCII includes NUL and control bytes; the label output preserves them. The
maximum nesting depth is 16 containers. Counts and byte-sized payload lengths
bound a whole packet to at most 65,539 bytes. Success exits `0`. Every protocol
error exits `1` and writes **no stdout**, even if earlier records were valid.
The driver stages output in a temporary file and publishes it only after the
whole packet passes. File or allocation failures also exit `1`.

## Revisions and independent cases

`base` allocates 17 bytes in `parse_label_record`, then copies an unchecked
payload and appends a terminator. The 26-byte `original_poc.bin` contains a
20-byte top-level label; the 28-byte `bypass_poc.bin` nests a 20-byte label.
Both trigger ASan `heap-buffer-overflow` in the baseline.

`correct` adds `rec_len > 16` inside the shared label parser, protecting every
caller. `incomplete` checks only the top-level branch in `parse_packet`, leaving
nested labels vulnerable. `regression` checks `rec_len == 0 || rec_len >= 16`,
fixing the overflow while rejecting the valid empty and 16-byte label cases.
`hardening_weak` has the full security guard but removes stack protection and
changes ELF binding from eager to lazy. Its Linux release binary loses Canary
and Full RELRO; the expected validator outcome is a warning with exit `0`.

`tests/tlv_parser/oracle_manifest.json` contains literal, protocol-derived
expectations for 24 cases, including both compact exploits. Outputs were not
generated by executing the target. `tests/test_tlv_target.py` builds the actual
patched sources and checks protocol behavior, atomic error output, count and
nesting bounds, sanitized vulnerabilities, boundary regressions, and Linux ELF
hardening degradation.

Build directly with `make -C examples/targets/tlv_parser/base release` or
`sanitized`. Both use Clang; release hardening flags are platform-aware, while
sanitized builds enable ASan/UBSan and preserve source-symbolized stacks.
Run `python -m unittest tests.test_tlv_target -v` for the focused checks.
